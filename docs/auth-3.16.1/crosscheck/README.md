# Round 2 交叉验证协议

**启动条件：** `round1/01`–`04` 四份报告全部落盘，且 Round 1 子代理已返回摘要。

**目标：** 不信任 Round 1 的任何结论，独立从 3.16.1 源码重新推导；专门找：

1. **字段名对、语义错**：例如把 `phase` 当成 `displayStatus`、把 `lastActivityAt` 当秒；
2. **只在某个分支成立**：例如「401 一定是 token 过期」忽略了设备离线/sid 失效；
3. **旧基线残留**：把 3.15.3 的 `hash`/HMAC/顶层 `tasks` 带进 3.16.1；
4. **网页与桌面端证据混淆**：把桌面端 `buildBootstrapResult` 的行为当成网页客户端行为；
5. **缺失分支**：刷新/重载/跨标签页/登出/过期/取消/错误码/重试；
6. **坐标不可复现**：偏移、片段、文件哈希对不上。

## 每路交叉审计的输入

- 4 份 Round 1 报告；
- `Reference_web/3.16.1/`（当前基线，独立重读）；
- 桌面端 `app.asar`（只读，按需）；
- 本项目实现（`rust/`、`android/`）用于差异核对；
- 旧基线归档 `archive/pre-3.16.1-auth/`（只用于识别旧结论残留，不作当前规格）。

## 输出

`crosscheck/0X-*.md`，每份必须包含：

1. **裁决表**：Round 1 的每条关键结论 → `CONFIRMED` / `CONTRADICTED` / `MISSING` / `UNVERIFIED`；
2. **纠错**：`CONTRADICTED` 必须给出正确结论 + 新坐标 + 原文；
3. **补漏**：Round 1 没覆盖但源码存在的分支/字段；
4. **旧基线残留清单**；
5. **网页/桌面端证据混淆清单**；
6. **最终可信结论集**（供合成使用）。

## 纪律

- 不修改 Round 1 报告；只写自己的 crosscheck 文件。
- 每条裁决有坐标；无法确认标 `UNVERIFIED`，不要用「应该」「大概」。
- 最终回复父对话 ≤15 行：报告路径 + `CONFIRMED/CONTRADICTED/MISSING` 数量 + 最重要的 3–5 条纠错。
