## 1.2 四条陷阱警告（**都是本轮实测踩到的**）

### ⚠️ 陷阱警告一：**`git HEAD` 不是批次前状态，别拿它当基准**

本工作区的 `HEAD` 比"第 3 批结束时的现场"**更旧**（例如 `HEAD` 的 `inject.js` 是 3749 行、还带着 `startHeartbeat`/`RECONNECT_MIN_GAP_MS`）。
⟹ **`git diff` 会混入并非本批所做的改动**（4b 实测：混进 75+/110−）。
**第 4 批的真实改动基准是批次前逐文件快照**；后人做隔离回归或改动审计，一律以快照为基准。

> **配套事实**：第 4 批的快照**已于收工时删除**；但第 4 批的结果**已提交为 `b627610`**，
> 所以**现在用 git 历史做基准即可**（`b627610^` = 第 1–3 批后的状态）。
> **写代码前的两条自保**：① **拍快照要覆盖"本批可能触及的全部文件"，不是预判清单**——本轮只拍了 8 个文件，
> 结果 `ShellRuntime.kt`/`TaskStore.kt`/`NativeRelayClient.kt` 都没进去，差点做不成隔离回归。
> ② **改动落地后、跑真机回归前，先给"改完的完整树"拍快照**，否则隔离做完就回不去了。
>
> **⚠️ 数字口径提醒**：`--numstat` 是权威值。4b 自报的两份 diff 相加后比 `--numstat` **少算 4+/2−**
> ⟹ **自报 diff 仅供参考，隔离回归请直接用快照文件整体回退，不要用 diff 拼。**

### ⚠️ 陷阱警告二：文档里出现"看门狗"时，**先看主语**

清点报告曾建议订正一句含"看门狗"的注释——**那句的主语是「页面自己的」看门狗**（原文语境是"页面做不到…"），
照抄会**把页面自己的机制记到壳的账上**。4b 子代理发现并只做了消歧。
⟹ **后人订正文档时，凡遇"看门狗/心跳/重连"一律先确认主语是壳还是页面。**

### ⚠️ 陷阱警告三：**删除类改动不能用「grep = 0」当验收判据**

父代理独立复核 4b 时，对 8 个"已删"符号 grep 得到**非 0 命中**（`stallArm` 2、`stallFire` 3、`zombieSuspected` 3…），
一度看起来像"没删干净"。逐行查看后确认：**10 处命中全部是注释**，形如
"已一并删除：它们唯一的读者 `zombieSuspected` 随看门狗决策机器（§5c）消失后…"、
"60s 这个数值取自被拆掉的看门狗那个 `STALL_REARM_COOLDOWN_MS`"、"历史取证（原 `CONVERSATION_STALE_MS = 60000` 的注释…）"。
⟹ 代码确实删净了，**这些注释反而比"0 命中"更好**：后人 grep 到会立刻知道"它存在过、已被删除"，而不是以为从未有过。

**由此两条纪律**：

1. **验收判据应是「残留命中是否都在注释里」**，而不是"命中数 = 0"；否则会把解释性注释误报成漏删。
2. 本轮两处**口径不一致**（`gaveUp` 用中文描述、不写字面名；其它符号在"已删除"注释里写了字面名）。
   **后者更好**（可 grep 到"已删除"的事实）。后续批次请统一采用后者。

### ⚠️ 陷阱警告四：**在"日常使用的真机"上跑侵入式诊断，必须先想清后果**

第 4 批 4a 的回归用了项目自带的 `carrier_takeover`（**故意把页面连接顶掉，让桌面端 KICK**）。
父代理在**用户日常使用的手机**上跑它，结果：

1. 页面被 KICK ⟹ 90s 测试窗口内回不来 ⟹ 测试结束后"入站帧静默 ≥35s"的**常规判死逻辑立刻真的接管**；
2. 于是进入"原生持连接 ↔ 页面反复重连被 KICK"的循环 ⟹ **用户看到界面一直在闪**；
3. 期间运行中的一个任务以 `completedInterrupted` 结束（**不能排除**与反复开多工作区桥有关——
   `inject.js` 注释记过"原生扫全部工作区会让桌面端把 host 收掉"）。

**纪律**：

- 侵入式诊断（任何会 KICK/顶掉连接的）**要先评估"跑完之后谁来收拾"**，并预先想好恢复步骤；
- **跑完必须把开关类状态还回原值**（本次为 `carrier_off` → 事后 `carrier_on`）；
- 出事后**先恢复用户设备、再解释、再继续**；
- 恢复手段的优先序：`carrier_stop`+`carrier_off` → 仍不行则 `force-stop` + `am start`（页面重新加载）。

**用户对此的明确表态（2026-09-18）**："你不用顾虑我，直接跑，只要能把 bug 潜在地找出来就好。"
⟹ 后续仍可跑侵入式诊断，但**上述恢复纪律不变**。

## 1.3 子代理失败后：**先查树的一致性，不是重派**

第 4 批收尾时**两个子代理接连在完成前失败**（无收尾消息）。其中 4c-B 的失败点恰好是"改 `inject.js` 之前"，
于是树处于**破损状态**：

- `zcode-protocol.js` 已删除 `RemoteClient.prototype.acceptPayload`；
- `inject.js` 仍在 `try { target.acceptPayload(frame.payload); target.acceptObservedPayload(frame.payload, false); }`
  里调用它。

**为什么这是真危害**：调用不存在的函数会抛异常，而**那一行与被动观察同在一个 `try` 里**
⟹ 异常会**连带跳过 `acceptObservedPayload`**，等于**打断活的被动观察管线**。
**实测证据**：`inject.test.js` 由 45/45 掉到 **42/45（3 项失败）**。

**处置**：父代理自己修好（删掉那个死调用，并留墓碑注释说明"留着会连带跳过被动观察"），
并收完子代理没做完的部分——`ShellRuntime.kt` 的 `bridges=` 假指标、`README` 共 10 处数字与表述、
`fake-desktop.js` 头注释、三个传输类的类头注释。修复后 `inject.test.js` 回到 **45/45**。

> **纪律**：**子代理失败后，第一件事是"查树的一致性"（定义与调用点是否成对），不是重派。**
> 判据：`node --check` 两个 JS + 两套 Node 测试 + `python tools/check_kotlin_structure.py`。
> 尤其要看**"删除定义"与"删除调用点"是否落在同一批里完成**——跨文件删除最怕只做了一半。

## 2.3 真机验收的通用手法

**⚠️ 盲点坐标会失败**：第 1 批按截图目测点「查看诊断日志」点了两次都没中。正确做法是
`adb shell uiautomator dump` → `adb pull` → 正则取 `text="…"` 的 `bounds="[x1,y1][x2,y2]"` → 点中心。
（第 3 批实测该行 bounds `[98,2221][1139,2302]` → 中心 **(618,2262)**，一次点中。）

**⚠️ 诊断弹窗的正文不在节点树里**（整块多行 `TextView`）：`uiautomator` 只能拿到标题与按钮，
所以**要看正文必须截图 + 读图**，别指望 dump。

**⚠️ 窄窗口打不中**：`am start` 自身进程开销就 ~100ms，而一次网页加载只用 ~300–400ms ⟹ 逐条精确
打进"新文档已开始、注入未就绪"的窗口在 adb 层做不到。**改用突发法**：把脚本 `adb push` 到
`/data/local/tmp/` 再用 `adb shell sh` 跑，**设备侧连发命令以横跨窗口**（第 1 批的 A/B 就是这么做的）。

**其他可复用事实**：判据优先看**日志顺序与计数**（比截图硬），截图用于"UI 是否渲染正确"。

**第 3 批的 5 步（已执行并全部通过，留作模板）**：

| 步 | 命令 | 期望 |
|---|---|---|
| 1 | `am force-stop` 后 `am start -a …DIAG --es diag_cmd vitals` | 受理 1 / **执行 1** / 失败模式（无处执行、放弃）**0**；且 `页面体征` 必须出现在 `注入脚本已就绪` **之后** |
| 2 | 退后台后 `am broadcast -n com.zcode.remote/.DiagReceiver -a …DIAG --es diag_cmd stall_state` | 后台通道回归基线 |
| 3 | 同后台通道换 `vitals` | 受理 1 / 执行 1 |
| 4 | `am broadcast … --es diag_cmd passive_off` | **应仍然无效**：「被动旁观已」=0 且「网页开始加载」=0，注入层回 `未知诊断指令` |
| 5 | `OPEN_SETTINGS` → dump 取坐标 → 点「查看诊断日志」 → 截图 | `注入脚本：已就绪`、`保留服务：运行中`、工作区数、日志路径正常 |

## 2.4 🔧 可复用配方：CDP 真机网页调试（端口 39385）

**这是本轮最有价值的工具**——能**在真机页面上直接求值**，把"猜页面行为"变成"读页面事实"。

```powershell
# 1) 找 WebView devtools socket（⚠️ App 重启后 pid 会变，必须重找、重转）
adb shell "cat /proc/net/unix | grep -o 'webview_devtools_remote_[0-9]*' | head -1"
# 2) 转发
adb forward --remove-all
adb forward tcp:39385 localabstract:webview_devtools_remote_<pid>
# 3) 求值助手（已随本次迁移保存）：E:\Zcode_harmony\docs\tools\cdp.ps1
pwsh -NoProfile -File docs\tools\cdp.ps1 -Expr "JSON.stringify(history.state)"
pwsh -NoProfile -File docs\tools\cdp.ps1 -Expr "document.body.innerText.slice(0,200)"   # 读屏上内容
```

前提：应用**已开** WebView 调试（`MainActivity.kt:235`、`ShellRuntime.kt:1307`）。
**典型用途**：读 `localStorage`/`history.state`、读屏上正文（判"是否进了任务详情页"）、验证页面侧机制。
⚠️ 页面 bundle 是**压缩成一整行的 4.78 MB**，`Select-String` 会打印整行 ⟹ **必须取匹配点周围的窗口**，别整行输出。

> 脚本本体见 [`tools/cdp.ps1`](tools/cdp.ps1)（**整份迁入，未改一行**）。

## 2.5 观测纪律（第 4 批新增，后人照做）

1. **日志会轮转**（上限 512 KB，切成 `zcode-shell.log.1`）⟹
   **读窗口必须 `cat` 两个文件**，否则会得到假阴性（父代理本轮被骗过一次：报"9 个关键词全 0"其实是没读到行）。
2. **不要用行号做窗口基准**（`wc -l` 的基准会在轮转后失效）；**用时间戳过滤**。
3. **跑侵入式诊断前先想好"谁来收拾"**，跑完把开关类状态还回原值。
