## 0. 一句话结论

**逐字锚点 0 死**：注入层现用的 **52 条**页面侧锚点里，**49 条存活**（其中 4 条换落点、不换字符串）、
**2 条需要适配**（`(max-width: 767px)` 断点收窄、`window.zcode?.log` 在 /remote/v4 包内消失）、
**1 条观察级风险**（`button[aria-haspopup="menu"]` 已是 Radix 运行时属性，页源码里搜不到字面量）。

**但 3.17.1 新增了一条会真正打断壳的机制**：桌面版本闸门（`desktopAppVersion` + URL `app_version`）。
在壳当前**不带 `app_version` 参数**加载 `/remote/v4` 的前提下，页面会
① 在未就绪时 `window.location.replace()` 自行改造 URL（多一次整文档导航、清空 `history.state`），
② 在已就绪时弹一个阻断式 modal「桌面版本已更新」并**停止一切 relay 发送**——
此时壳的轻推（合成 `online`）会被 `isBlocked()` 门死变成空操作，壳若照旧重载只会让对话框再次出现。
**这条是本次唯一必须动手的项。**

**对壳的实际影响（按严重度）**

1. **壳当前在 URL 里不带 `app_version`**（`grep -rn "app_version" android/` → 仅 `inject.js:2673` 的 `/remote/v4` 探针与注释，**无一处设置该参数**）。
   因此只要桌面端在 `bootstrap-response` 里回了非空 `desktopAppVersion`：
   - 页面未就绪 → **多一次整文档导航**（`location.replace`）。新文档的 `history.state` 为空 ⇒
     `pinChatRoute()` 预设的 `zcodeMobilePage:'chat'` 被清掉，页面落 `home`。
     壳的 `restoreChat`（document-start 重钉）能救，但该配置为假时救不了。
   - 页面已就绪 → **弹出阻断 modal，页面停止一切 relay 发送**。
2. **壳的看门狗会把这种"静默"误判成卡死**：页面端口不再发任何帧，而壳的轻推（合成 `online`）
   被 `isBlocked()` 直接门死（`B()` 首行返回）→ 轻推无效 → 走重载 → 重载后闸门再次触发 → **对话框循环**。
   `inject.js` 的"恢复推动"与 KICKED 自愈在此场景下都是负收益。
3. **原生承载不受影响**：壳自己的 relay 桥（Kotlin `RelayBridge`）是独立 socket，不走页面 `sendPayload`。

**建议动作（§5 P0/P1）**：① 别把"页面静默"当卡死的唯一判据，先排除"版本闸门阻断"；
② 让壳在重载前把已知的 `desktopAppVersion`（原生承载的 bootstrap-response 里就有）写进 URL 的
`app_version`，既消掉多一次导航、也消掉 modal；③ 若无法可靠取到该值，至少在重载前检测
`dialog[aria-labelledby="remote-version-title"]` 是否存在，存在则不重载（交由用户点"重新加载"）。

## 5. 需要改注入层的清单（按优先级）

### P0-1｜别让版本闸门把壳带进"重载 → modal → 重载"循环
- **位置**：`inject.js` 看门狗/`__zcodeShellNudgeRecover`/切「重载」的那些路径；以及原生侧的 reload 决策。
- **改法（推荐，一行级）**：重载判定前加一条闸门探测——
  `document.querySelector('dialog[aria-labelledby="remote-version-title"]')` 命中即**判定为"版本闸门阻断"**，
  不走轻推、不走重载，直接上报一个新状态名（如 `blocked`）交给原生提示用户。
- **理由**：该状态下页面被 `isBlocked()` 门死，轻推是空操作；重载会重现同一对话框。

### P0-2｜KICKED 自愈阈值与页面新增的一次重试对齐
- **位置**：`inject.js:1187-1365`（`KICKED_HEAL_CAP`/`KICKED_HEAL_STORE`/KICKED 分支）。
- **改法**：把"连续 KICKED 计数"改为**带时间窗**的判据——只有 **60 s 内出现第 2 次 KICKED**
  才认终态（与 `kickedDelay` 的 60 s 门槛一致）；单次 KICKED 不增计数、交给页面自己 2–5 s 重连。
- **理由**：页面 3.17.1 已内置一次 KICKED 重试；壳按旧假设在"第 2 次"就重载，会与页面终态路径互相踩。

### P1-1｜让壳的 URL 带上 `app_version`（消掉闸门本身）
- **位置**：原生 URL 构造/`RemoteUrl.kt` 与 `MainActivity.loadUrl` 附近（不在注入层，但决定注入层是否被闸门打断）。
- **改法**：从原生承载的 `bootstrap-response`（Kotlin 已在解析该帧）取 `desktopAppVersion` 并持久化，
  下次加载/重载时以 `app_version=<值>` 拼 URL；拿不到时**不猜**，退回 P0-1。
- **理由**：`_manifest.json` 的 `entryUrl` 本身就带 `app_version=3.17.1`；这是官方 URL 契约的一部分。

### P1-2｜保住 `history.state.zcodeMobilePage` 跨"闸门导航"
- **位置**：`inject.js:233-241` `pinChatRoute` 的调用时机。
- **改法**：把 `pinChatRoute()` 从"仅 `restoreChat` 时调用"扩为**每次 document-start 都调用**
  （幂等、`replaceState` 成本可忽略），这样 `location.replace()` 产生的新文档也会立刻重新钉住 chat 路由。
- **理由**：`location.replace()` 的新 history entry 状态为空，预设槽会被清掉；document-start 重钉是最便宜的兜底。

### P2-1｜`NARROW_QUERY` 与页面断点对齐
- **位置**：`inject.js:3237`。
- **改法**：`'(max-width: 767px)'` → `'(max-width: 767px) and (hover: none) and (pointer: coarse)'`。
- **理由**：页面手机壳的判据已收窄（主包 @3,226,116），否则窄视口 + 精确指针时状态条底色取错。

### P2-2｜给头部刷新钮的锚点加第二条判据
- **位置**：`inject.js:3923` `button[aria-haspopup="menu"]`。
- **改法**：并列接受 `[aria-label]` 命中主题菜单文案、或首位/末位候选回退；失败时保留现有 `warnRefreshOnce` 日志。
- **理由**：该属性由 Radix 在运行时写入（源码不可检索），页面换 menu 组件实现即会静默失效；
  当前"取最后一个 `menu` 钮"的写法在 3.17.1 恰好正确（头部只有 1 个），但没有任何机制保证以后仍正确。

### P2-3｜`window.zcode?.log` 沉降分支降级为观察（**不改代码**）
- 现状是幂等、零成本；不要为它新增依赖。仅把"页面日志"从可用观测面里划掉，改用 `mobile-diagnostic`。

### 观察项（不改）
`body *` 全量遍历成本；`data-mobile-chat-surface=inert` / `data-zcode-bootstrap-theme` / `zcode-theme`
三个现成新锚点是否值得替换现有判据；`mobile-task-view-update` / `mobile-log-pull-request` 是否要补实现。

## 6. 未复核 / 不确定项

1. **【待验证】`desktopAppVersion` 在真实桌面端的取值**：能否在 `bootstrap-response` 里稳定返回非空值，

   `appVersion: j()` 是 `x().max(64)` 的字符串）。3.17.1 桌面端是否仍接受 `3.6.5` **需抓帧确认**。

4. **【待验证】分片上限一致性**：页面侧新常量（`validation-B0HfQ5gr.js` @152,7xx 起：
