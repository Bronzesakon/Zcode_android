# 页面卡死看门狗 + 页面视觉观测 —— 死代码候选的功能影响分析

> 核验基线：2026-09-19 当前工作树（b627610 之后）
>
> 本域覆盖两个**必须分开看**的功能：
> **(a) 页面卡死看门狗** —— "点进任务长时间不出内容时，壳要不要动手救页面？"（现行政策：**不动手，只记录**；
> 其"决策机器"已于 2026-09-18 随第 4 批 4b 拆除，只剩量具）
> **(b) 页面视觉观测** —— 壳把网页的状态栏颜色、主题、滚动条宽度上报给原生，让手机顶部那条底色跟网页一致、滚动条不占位。
> 本域三条候选里，**D1 属于 (a)**，**C11 / C12 属于 (b)**。

## A. 本域功能概览（给非工程师看）

**(a) 卡死看门狗。** 起因是用户 2026-09-12 报的真症状：「长后台后点进某个任务，长时间不出内容」（README「已知问题 D2」）。壳（=这个安卓 App）当时想出来的办法是：注进网页的一小段脚本（下称**注入层**）每隔一会儿体检一次网页——输入框是不是灰着、标题是不是退回成「新建任务」、任务在跑但网页连接是不是一条帧都没有——一旦判为"卡死"，就按"轻推 → 刷新"两级动手。**这条路已被真机判决：** 日志里 `socket.close() 被调用 … 来自 …` 当场点名，是壳自己在 **40 秒里把网页正用着的连接拆了 10 次**；用户看到的"发消息转圈 / 要重连好几次才出来 / 返回页面是它自己在重连"全是它的下游（README「实现要点 14」，现 `README.md:454`）。于是 2026-09-15 定下**只读壳**政策：**壳永不关闭网页的连接、永不自动刷新网页**。四个"动手"函数的实现体在 2026-09-16 审计里被删掉，只留守卫和一行日志。
>
> ⛔ **决策机器本身也已拆除（2026-09-18，第 4 批 4b）。** 那套"布防 → 3 秒后判定 → 再 3 秒后放弃"的梯子、每秒一次的巡检定时器、`stallState` 及其全部字段、`gaveUp` 放弃位、僵尸订阅指纹（`zombieSuspected` + `ZOMBIE_*`）、页面日志失败事件布防（`PAGE_LOG_STALL_EVENTS`）与共用常量（`STALL_NUDGE_MS`/`STALL_RELOAD_CAP`/`STALL_REARM_COOLDOWN_MS`/`STALL_STORE_RELOADS`/`PAGE_LOG_STALL_EVENTS`）——**一行不留**（删除清单与取证见 `docs/18` §2.6/§5，及 `inject.js:2076-2082` 节头注释）。
>
> **保留下来的是什么：体征量具，改挂心跳（2026-09-19 核实仍然成立）。** `readVitals()`（DOM 体征快照）与 `vitalsStalled()`（卡态判据）没有随机器消失，而是搬进了**心跳 tick**（`inject.js:1414-1430` 的 try 块；心跳由原生泵每 10s 发令一次，`ShellRuntime.kt:847` `PUMP_INTERVAL_MS=10_000L`，前台不发、只后台）。上报口径沿用旧 60s 闸门（`VITALS_POST_MIN_GAP_MS=60000`，`inject.js:1139`）：**卡态边沿**（`vitalsStalled` 由假变真）立刻一帧 `why='stalled'`，其余每 60s 一帧 `why='periodic'`，**永不每跳一帧**；§5b 二次判定仍未就绪时补一帧 `why='giveup'`（`inject.js:1994`）。原生侧 `pagevitals` 分支（`ShellRuntime.kt:1961-1970`）照旧**只落日志不做判断**（`arm`/`cancel` 两个旧 why 值已随机器删除，别再按它们检索）。

**(b) 页面视觉观测。** 这个 App 没有自己的标题栏——手机顶部状态栏下面那条底色，必须跟网页当前的颜色一致（否则会有明显色块割裂）；网页自己的滚动条会在布局里占 14px，安卓 WebView 又画不出一条"同款"的滚动条。所以由注入层做两件事：① 读出网页当前处于哪个视觉状态 + 用了什么主题，**只报名字**，原生查表上色（`core/PageBarColor.kt`）；② 把滚动条宽度压成 0 并自绘一条悬浮指示条，原生把 View 层那条多余默认条关掉（`MainActivity.kt:244-254` 明确把这件事交给注入层）。
>
> 这部分**是活的、且是用户在意的**：状态栏底色一错用户立刻看得见；滚动条一回来内容就偏（README「实现要点 12」，现 `README.md:452`，记着硬数字：丢宽的是内部 `[data-v4-timeline-scroll]` 容器、根文档不丢（真机 `innerWidth==clientWidth==363`），而"滑块撑满 14px 轨道、视觉粗一倍"是**用户在真机上当场指出**的）。C11 / C12 当年只是这块机器里**错位的文档块**和**三处没人在意的残留**，不涉及功能本体（2026-09-19 复核：错位已修复、蕴含项已删，其余仍在且无害）。

## B. 本域架构小结

**(a) 看门狗**（都在注入层 `assets/inject.js` 里，原生侧只被动收帧；**⛔ 决策机器已于 2026-09-18 拆除，下图是拆除后的现状**）：

```
网页 DOM / 页面自己的日志 / 页面桥帧流
        │
        ├─ §5b 进对话铁判准（1692-2064）：「页面进对话了」信标 → 3s 后查一次
        │      未就绪再等 3s（STALL_RELOAD_MS，1749）判第二次
        │      终点 1：轻推      → nudgeReconnect(2276)          = 只写一行日志（空壳）
        │      终点 2：整体刷新   → reloadForMissingConversation(1989) = 一行日志 + postPageVitals('giveup')
        │
        ├─ ⛔ §5c 卡死看门狗决策机器（原 1995-2328）——已于 2026-09-18（4b）拆除
        │      现存 §5c（2064-2299）只剩**量具**：readVitals / vitalsStalled /
        │      postPageVitals / notePageLogEvent / nudgeReconnect
        │
        └─ 体征量具改挂心跳：heartbeatTick 的 try 块（1414-1430，泵 10s 一拍）
              卡态边沿 → postPageVitals('stalled')；否则 60s 一帧 'periodic'
              输出：`pagevitals` 帧 → 原生 ShellRuntime.kt:1961-1970 = 只落日志，不做任何判断
```

- **哪一块是本体？** 现在只有两类输出：① 体征量具（见上，`pagevitals` 帧 + `页面体征(why)` 日志）；② 拒绝动手的记账日志——`只读壳：不轻推页面 socket（本会触发的原因：…）`（`noteReadOnlyRefusal`，`inject.js:1178-1185`）、`只读壳：不因"…"重载页面（…）`（`:1993`）、`进对话 3s 未出对话详情…：只读壳不内推`（`:1968`）。这行"本会动手"的日志是"壳什么时候想动手"的诊断量（`inject.js:1174-1177` 的注释、原 README 判据速查表已被 README 重构吸收）。
- **⛔ 脚手架已清**：`stallState`（含全部字段）、`STALL_NUDGE_MS`、`STALL_RELOAD_CAP`、`STALL_REARM_COOLDOWN_MS`、`STALL_STORE_RELOADS` 的 sessionStorage 往返、`zombieSilenceS`、`lastReloadAt`、`reloadCount`、`streamStalled`、`gaveUp`、1 秒定时器 `conversationStreamStallTick`、僵尸订阅指纹——全部已于 2026-09-18（4b）删除。**`STALL_RELOAD_MS`（1749）是唯一幸存的 STALL_* 常量**：名字里的 "RELOAD" 是历史遗留，现在只表示"§5b 第二次判定的延时"（值 3000，无任何 reload 语义）。
- **要保住"能动手"的能力，哪部分必须留？** **答案是：已经保不住了。** 三个"动手"函数现在全是"记一行 + `return false`"（`forceReconnect:1483`、`nudgeReconnect:2276`、`reloadForMissingConversation:1989`；第四个 `stallReloadIfAllowed` 连函数都没了），实现体在上轮审计里已删。开关常量 `SHELL_READ_ONLY`(1169) 仍然**必须留**——它另外被回前台那条路上的两条守卫真实读取（现 `2972`/`2987`），其中 `2972` 的只读分支里跑着另一个活功能（回前台死链兜底 `healDeadLinkOnResume`，`:1225`）；但**把开关改回 `false` 并不能恢复动手**，因为实现体不在了。"留着开关以便做对照实验"这个理由，今天已经不成立。

**(b) 视觉观测**（`inject.js` §6/§7 + 原生；行号为 2026-09-19 当前值）：

```
网页 DOM（主题标记 / 断点 / 状态类）
   → §6 installPageStateReporter（3250，boot 于 3687）→ reportPageState（3003）
   → 原生 ShellRuntime.onPageState（1827）→ PageBarColor.kt 查表（判据日志 `状态栏底色: …` 在 PageBarColor.kt:90）→ 状态栏底色

网页布局（内部滚动容器的 offsetWidth-clientWidth）
   → §7 installScrollbarWidth（3344，document-start 主道，boot 于 3684）
   → §7 自绘悬浮条 barElement（3475，调用于 3557）
   → 原生 MainActivity.kt:244-254 关掉 View 层默认条（isVerticalScrollBarEnabled=false 在 :254）
   → 量具：reportViewport（3049，启动 +1.2s 与每次 resize 后 300ms 各报一行，boot :3706-3709）
```

- **本体**：`installPageStateReporter` / `installScrollbarWidth` / 自绘条 / `MainActivity` 的那几行。
- **脚手架/量具**：`reportViewport` + `scrollbarReport`（3021，"14px 有没有真的还回来"的唯一硬判据）。
- **测试覆盖不对称**（2026-09-19 复核更新）：§6 有单测钉（`tools/inject.test.js` 的 `pageStates(...)`，现为 1156/1164/1170/1176/1191/1197/1211/1218/1235/1241/1261/1270 等十余项断言），§7 **零断言**（全文件只有 `:1253` 一句注释提到 `installScrollbarWidth`），§7 的真机验收记录在 README 与 `docs/18` 里。**动 §7 必须上真机**，这是本域唯一"没有自动护栏"的地方。
